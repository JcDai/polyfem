# miso

Vendored from [hocgv-miso](https://github.com/fsichetti/hocgv-miso): miso-generated
solvers used by `polyfem::utils::Jacobian` for robust Jacobian validity checks
(static injectivity and continuous geometric validity).

- `EigenAdapters.hpp`: hand-written Eigen-MiSo glue (node-order permutation
  tables and factory functions), included directly by
  `src/polyfem/utils/Jacobian.cpp`.
- `DegenerateAdapters.hpp`: the same for the P3 degenerate checks
  (`P3{Tri,Tet}Deg{Val,CGV}`, `JacEval_P3{Tri,Tet}Bernstein`), which take the
  Bernstein coefficients rest + displacement as intervals.
- `generated/`: machine-generated by [pymiso](https://gitlab.com/minimize-solve/pymiso)
  via `generate.py`.

## Regenerating

Dependencies

- `sympy`

```
python generate.py                # everything
python generate.py --degenerate   # only the degenerate classes
```

This clones `pymiso` (branch `polyfem-degenerate`) into a gitignored
`ignore/pymiso` (if not already present; set `POLYFEM_PYMISO_DIR` to use
another checkout) and regenerates everything under `generated/` in place.
The degenerate classes sample at the points of polyfem's quadrature rule of
order 4, which `generate.py` reads from `src/polyfem/autogen/auto_*.ipp`
and records in `generated/DegenerateRules.hpp`; polyfem checks at runtime
that its rule is still that one.

The top-level `generated/CMakeLists.txt` is polyfem's own: keep it when
regenerating (pymiso's version fetches misolib again) and drop the generated
`include.hpp`, which nothing uses.

## Provenance

Vendored from hocgv-miso at commit `aaab372d086608ab717ecb9ba0e7bc0fe00c7a10`,
which is the commit the former `cmake/recipes/hocgv_miso.cmake` pinned, so
vendoring did not change any generated code.

Since regenerated in-tree with pymiso `5d0961b` (which reproduces the vendored
code exactly from the original `generate.py`), after two changes to the
generator: the rest positions and the displacements are separate inputs, so
their sum is formed in interval arithmetic, and the P1 continuous check is a
one-variable problem in t.

The degenerate classes (`DegenerateChecks` in `generate.py`) need pymiso's
degenerate inclusions, restricted degenerate faces, the cone subdivision with
alternation, and sampling at given points; the classes above are unchanged by
those additions.

`misolib` (the interval-arithmetic solver these generated problems are built
against) is *not* vendored: it stays an external dependency, fetched by
`cmake/recipes/misolib.cmake`.
